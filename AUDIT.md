## 1. РОЛИ И ДОСТУП (ТЗ §2, §10)

### ✅ Реализовано
- **5 ролей**: player, curator, leader, specialist, master — в БД и коде
- **История смены ролей** (`role_history` модель + `change_role()` сервис)
- **Ограничение по ролям**: `require_role()` в API, role checks в боте
- **Мастер может назначать все роли** (`POST /users/{id}/role`, require_role("master"))
- **Меню команд** (☰) с разграничением ролей

### ❌ Не реализовано
- **Лидер может назначать Кураторов** (ТЗ 4.7): в коде только Master, а ТЗ говорит «Мастером или Лидером»

### ⚠️ Частично
- **Назначение Специалиста**: роль специалиста существует, но
  - Нет UI для назначения как "приглашённый эксперт"
  - Нет workflows для назначения группы специалисту
  - Специалист не имеет особых прав高于 player除了 /myteam

---

## 2. КУРАТОР (ТЗ §4.7, §10)

### ✅ Реализовано
- `/myteam` — список подопечных (streak, оплата)
- Группы (`Group` модель, type="curator", max_members=10)
- Доступ к чтению users/progress в админке (require_role: master,leader,curator)

### ❌ Не реализовано
- **Назначение группы куратору через UI** — модель есть, но нет endpoint для привязки/отвязки игроков к группе куратора
- **Завершение квеста → повышение до куратора** — нет автоповышения

---

## 3. ЛИДЕР (ТЗ §4.7, §4.10)

### ✅ Реализовано
- `/clan` — создание кланов (clan_router)
- Модель Clan + ClanMember
- Админ-доступ к audit, dashboard, scrolls, payments (read)

### ❌ Не реализовано
- **Управление кураторами** — Лидер не может назначать кураторов (только Master)
- **Управление потоком до 100 игроков** — нет mechanics для этого
- **Создание кланов** — handler есть, но нет назначения игроков в кланы через UI
- **Кураторы курируются Лидером** — нет UI для этого

---

## 4. СПЕЦИАЛИСТ (ТЗ §4.8, §10)

### ✅ Реализовано
- Роль `specialist` в БД
- `/myteam` (входит в MENTOR_ROLES)

### ❌ Не реализовано (критично)
- **Создание доп. квестов для своей группы** — нет ни одной строки кода
- **Нет UI** для создания/публикации доп. квестов
- **Нет модели** для specialist-specific quests (в ТЗ: "создаёт дополнительные квесты для своей группы")
- **Нет API** для CRUD доп. квестов
- **Нет доставки** доп. квестов игрокам группы

---

## 5. ГРУППЫ И КЛАНЫ (ТЗ §6, §4.10)

### ✅ Реализовано
- `Group` модель (owner_id, type, name, max_members)
- `Clan` модель (owner_id, name)
- `ClanMember` модель (user_id, clan_id)
- `user.group_id`, `user.clan_id` в User модели
- `/clan` создание кланов

### ❌ Не реализовано
- **Управление группами в админке** — нет CRUD для групп
- **Назначение игроков в группы** — нет UI
- **Назначение владельца группы** — нет UI
- **Агрегированный прогресс кланов** — нет вычисления
- **Рейтинг кланов** — нет

---

## 6. КОМИССИИ (ТЗ §4.7, §8)

### ✅ Реализовано
- `CommissionBalance` модель (total_earned, total_pending, total_paid_out)
- `calculate_commission()` — авто-расчёт при первом платеже реферала
- Вызов в `finalize_successful_payment()`
- **Конфигурируемый %** в settings (`mentor_commission_percent`)

### ❌ Не реализовано
- **Выплата комиссий** — нет endpoint для "выплатить" (mark as paid_out)
- **Просмотр баланса куратором** — нет команды/кнопки для куратора видеть свой баланс
- **Экспорт для бухгалтерии** — нет

---

## 7. ПРИЗОВОЙ ФОНД (ТЗ §4.9)

### ✅ Реализовано
- `PrizeFund` модель (total_amount, percent_rule, status)
- `PrizeFundPayout` модель
- API endpoints (GET/POST) для Master

### ❌ Не реализовано
- **Распределение фонда** — нет логики автоматического распределения
- **Отображение игрокам** — нет

---

## 8. ЛИЧНАЯ ТРОПА (ТЗ §4.12)

### ✅ Реализовано
- Отчёты отправляются от имени System (но в чат игрока, а не Мастера)
- Согласие на ПДн (`consent_at` в User)

### ❌ Не реализовано
- **Дублирование отчётов в чат Мастера** — нет Mechanics
- **Фильтрация по потоку/куратору** — нет

---

## 9. УВЕДОМЛЕНИЯ (ТЗ §4.11)

### ✅ Реализовано
- Evening reminder (если Свиток не выполнен)
- Streak loss warning
- Pending notifications queue

### ❌ Не реализовано
- **Системные уведомления** о смене роли, старте потока — нет

---

## 10. АДМИН-ПАНЕЛЬ (ТЗ §7)

### ✅ Реализовано (API)
- Дашборд (`GET /dashboard`)
- Контент (scrolls, daily-scrolls CRUD)
- Пользователи (список, прогресс, смена ролей)
- Финансы (payments, commissions, prize-funds)
- Модерация (reports, resolve)
- Аудит (audit log)
- Настройки (settings CRUD)

### ❌ Не реализовано
- **Фронтенд админки** — есть только API endpoints, нет React SPA
- **Управление группами** — нет CRUD для groups в API
- **Назначение игроков в группы** — нет
- **Назначение Специалиста и его квестов** — нет
- **Распределение призового фонда** — нет
