**Admin can configure platform settings, view audit trail, and UI respects role permissions.**

  <action>
    Expand `src/app/api/routes/admin.py` with settings management and audit log endpoints.

    **Settings endpoints (require role: master only):**

    1. **GET /api/admin/settings** — List all settings:
       - Query Setting model, return as `{ settings: [{ key, value, created_at, updated_at }, ...] }`
       - Order by `key ASC`

    2. **PUT /api/admin/settings** — Update settings (bulk):
       - Request body: `{ settings: [{ key: str, value: str }, ...] }`
       - For each setting: upsert (insert if key doesn't exist, update if it does)
       - Use `INSERT ... ON CONFLICT (key) DO UPDATE` pattern or separate queries in transaction
       - Create AuditLog: action="settings_updated", details=f"updated keys: {list of keys}"
       - Return updated settings list

    3. **GET /api/admin/settings/{key}** — Get single setting value

    **Audit log endpoints (require role: master, leader):**

    4. **GET /api/admin/audit** — List audit log entries:
       - Query params: `action: str | None = None`, `admin_id: UUID | None = None`, `page: int = 1`, `page_size: int = 20`
       - Return `{ entries: [...], total: int, page: int, page_size: int }`
       - Entry object: `{ id, admin_id, admin_name: str | None, action, details, created_at }`
       - Left-join with User to get admin_name from admin_id
       - Order by `created_at DESC` (newest first)

    5. **GET /api/admin/audit/{entry_id}** — Single audit entry detail

    **Pydantic models:**
    - `SettingUpdateRequest(BaseModel)`: settings: list[SettingItem]
    - `SettingItem(BaseModel)`: key: str, value: str
    - `SettingResponse(BaseModel)`: key, value, created_at, updated_at
    - `AuditEntryResponse(BaseModel)`: id, admin_id, admin_name, action, details, created_at
    - `AuditListResponse(BaseModel)`: entries, total, page, page_size

    Use `async with get_session() as session:` pattern.
